# Route families, routes as E2B codes, and drug-class groups

For anyone checking how a drug record's route is cleaned (`rules/drug-route.md`), or reusing the route families for FDA labels.

`families.csv` says, for every value FDA writes about how a drug was given, every route family a drug given that way could be in. The label flags read it for reports and for labels alike, so a report and a label are compared in the same terms. `route.csv` reads each FAERS route word as one code of ICH's E2B route list (code list 14), `e2b_route.csv` names those codes, and `atc_group.csv` gives a code its drug-class group. The release build reads them into `drug_route_T`; FDA's own values are never changed.

## The files

| File | Rows | What |
|---|---|---|
| `families.csv` | 504 | `source`: where the value is written (`route`, FDA's route field; `dose_form`, FDA's dose form field; `drugname`, a form word in the drug name; `label`, a route name on an FDA label); `value`; `families`: the families it allows, sorted and joined with `;`, empty when it says nothing; `decided_by`: both runs agreed, the union of the two runs, an accepted reviewer correction, or FAERS evidence (the union less a family FAERS shows only as a mistake); `reason`, where the value allows several families or is unusual |
| `route.csv` | 265 | `route`: a route word as compared (lower case, spaces collapsed and trimmed); `code`: its E2B code; `evidence`: why |
| `e2b_route.csv` | 67 | `code`, `e2b_route`: E2B's name for it |
| `atc_group.csv` | 19 | `code`, `e2b_route`, `group`: the drug-class group the WHO class choice uses; a code not listed is in no group |
| `review/` | | how `families.csv` was made: the instruction, both runs, the corrections with whether each was accepted, and the families FAERS evidence removed (`evidence-removals.csv`) |

## How each was made

- **`families.csv`.** The values are every route word FAERS uses that `route.csv` reads, the 126 dose forms on at least 5,000 suspect drug records each, the form words of drug names, and the route names on FDA's human prescription labels. Each was placed by following one written instruction, `review/instructions.md`: list every family plausible for a real product given that way, one family only when no other is plausible, none when the value says nothing. Two independent runs followed it, each without seeing the other (`review/run_a.csv`, `review/run_b.csv`). Where they agreed the value keeps their families; where they differed it takes the union of both. A reviewer then checked the result and proposed corrections, each with its reason and confidence, in `review/corrections.csv`; a correction is applied only where its `accepted` column says `yes`, and marked in `decided_by`. A family is added to a value only when FAERS has real cases of it given that way; a correction that adds a family for a product FAERS has no reports of is not accepted. Last, FAERS's own records were read for every value that allows several families (notebook `11_drug_route`, section 4). A family is removed from a value only where FAERS shows it is only ever a mistake: every drug behind the records that pin the value to that family is one never given that way. Five were removed, each listed in `review/evidence-removals.csv` with the records and drugs behind it, and their rows say `FAERS evidence` in `decided_by`. Two kinds of family stay although no FAERS record pins a value to them. A family that no independent clue ever allows stays: absence of evidence is not evidence. For many such values FAERS has no record that could show it (`po`, `intraduodenal`), and some families are real uses no clue can see (talc into the chest, an intestinal gel into the duodenum). A family that a clue allows but never tells apart from another stays too: both families are real products (lidocaine patches act on the skin, fentanyl patches through it; eye injections are injected), dropping either would be a coin toss, and the label flags settle most such records by overlap, because only one of the ingredient's labels matches. Anyone can rerun it: give the instruction and the values to two independent runs, take the union, review, and read FAERS.
- **`route.csv`.** In order: every E2B route name as written; the same name written as on EDQM's list (`Oral use`, `Intravenous use`); other spellings FAERS uses for an E2B route (`Iv drip`, `By mouth`, `Intravitreal`, which E2B files under Intraocular); every route name on FDA's human prescription labels, the ones E2B lacks read as the nearest E2B route (`Infiltration` and `Soft tissue` as Parenteral, `Subarachnoid` as Intrathecal, `Intracaudal` as Epidural, `Intracanalicular` as Ophthalmic, `Transmucosal` as Oropharingeal); and every other word DiAna's route table reads (`route_st.csv`, DiAna, CC BY 4.0, see NOTICE), through the E2B route of DiAna's standard route. Feeding tubes and other routes E2B has no name for read as `050` Other. The 87 words that remain, on 131 drug rows in all of FAERS (`Via g-button`, `Arm`), read as nothing.
- **`e2b_route.csv`.** The 67 routes of E2B code list 14, as ICH publishes them in its E2B(R3) implementation package.
- **`atc_group.csv`.** The groups the WHO class choice reads a record's route in, rule atc-class-choice, which gives each group the codes it fits (`eye`: Ophthalmic, Intraocular, Subconjunctival, Retrobulbar; `ear`: Auricular (otic); `nose`; `lungs`; `skin`: Topical and Cutaneous; `vagina`; `mouth`: Oral; `injection`: the three intravenous codes, Subcutaneous, Intramuscular, Intra-arterial, Parenteral; `transdermal`), each FDA route word read into its group through its E2B code.

## Review

`families.csv` is the reviewed table the release reads, as accepted. A later change to any row is its own reviewed change, with its reason, made the same way.
