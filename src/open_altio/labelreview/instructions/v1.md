# How to code a label phrase

You help one pharmacovigilance reviewer code phrases from FDA drug labels into MedDRA preferred terms. Fixed rules have already coded most label text. The items in this folder are the phrases the rules left uncertain: phrases that read like reactions but matched no term, and phrases where a rule's match may be wrong.

For each phrase you answer one question, given below with its rules: which MedDRA preferred terms the phrase states as a reaction to this drug. Your answer is never a decision. The reviewer accepts or changes it, and rules then compare the coded terms with every report of the drug, so code each phrase with care.

## What to read and what to write

1. Read this file to the end. Everything you need is in it, in `items.jsonl` and in `preferred_terms.txt`; look nothing up elsewhere.
2. Read `items.jsonl` in this folder. Each line is one item, a JSON object with `item_id`, `drug`, `section` (the label section), `sentence` (the label phrase), `rules_guess` (a preferred term the rules thought of, or empty; it may be wrong) and `why_uncertain`.
3. Write `suggestions.jsonl` in this folder: one line for each item, each a JSON object with exactly these six keys:
   - `item_id`: copied from the item.
   - `pts`: a list of the MedDRA preferred term names the phrase states as a reaction to this drug. Every name must be a line of `preferred_terms.txt`, spelt exactly as it is there (search it; do not read it whole). An empty list when it states none.
   - `none_reason`: when `pts` is empty, one reason key from the list below. Otherwise empty.
   - `note`: for the reason `other` only, why none of the reasons fits. Otherwise empty.
   - `evidence`: when `pts` is not empty, the words of the phrase that state them, copied exactly, character for character. Otherwise empty.
   - `reason`: one or two plain sentences the reviewer can check against the label.
4. If you will not or cannot answer an item, write its line with an empty `pts` and an empty `none_reason`. Never use `other` for that. Answer each item once; do not try an item again or hand it to another model.
5. If `problems.txt` is in this folder, your last `suggestions.jsonl` was refused for the reasons it gives. Write a new one that avoids them.
6. Change no other file.

One line of `suggestions.jsonl` looks like this:

```json
{"item_id": "3f2a9c0d1e4b5a67", "pts": ["Gynaecomastia", "Galactorrhoea"], "none_reason": "", "note": "", "evidence": "Galactorrhea, amenorrhea, gynecomastia", "reason": "The phrase lists these as reported with prolactin-raising drugs; UK spellings in MedDRA."}
```

## Principles

1. Name only preferred terms from `preferred_terms.txt`, never lower level terms. One name not in it refuses the whole file when it is imported.
2. Code what this phrase says about this drug. Use medical knowledge to read the words, but not what you know about the drug from elsewhere.
3. Name every reaction the phrase states, and no more. An umbrella phrase ("injection site reactions") states its umbrella term; the reactions it lists in brackets are stated too.
4. Do not decide whether a report is expected. That is for the rules that compare the coded terms with each report.
