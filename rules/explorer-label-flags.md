# How the screens show the label flags

A label flag says whether today's US prescription label of a suspect drug lists a reaction. The flags come from the release's `label_flags_T`, and the explorer reads each the way the label flags step wrote it, never deciding one again. The explorer shows them where the release holds the tables they are read through: `label_flags_T`, `drug_rxnorm_T`, `drug_substance_T` and `label_candidates_T`, which names each label read, with `ingredient_rxnorm_T`, each ingredient's own code. A release without the first four shows no flags, no Label status filter and no problem.

- **Which flag a record has.** The drug records that carry a flag are those the label flags step flags (`suspect_roles` of rule label-flags, by FDA's role code as published), so a person's own roles there reach the screens too. A record DiAna marks as a trial product has none. A record finds its row in `label_flags_T` by its RxNorm code (`drug_rxnorm_T`), its candidate route families (`route_families_T` in `drug_route_T`, sorted and joined with ";", empty when nothing is known, and empty for every record of a release without `drug_route_T`) and the reaction as FDA published it. A record with no RxNorm code finds the row the step wrote for it, no label found, so it is shown, never left out.
- **A drug's page.** Its flags follow what it counts (rule explorer-drug-counts). Counting any product containing an ingredient, as a page opens and as the Statistics tab always counts, every reaction counted is judged against the ingredient's own label: each record holding the ingredient, a combination's included, finds the row the label flags step wrote for the ingredient's own code (`ingredient_rxnorm_T`), so Entresto's reports on valsartan's page are read on valsartan's label. An ingredient with no label of its own, in any form, gives Not compared, no label found for the products that hold it with others, while a record of the ingredient alone keeps its own flag, by its own code, where that code names the ingredient: insulin's own reading gives no code, so LANTUS's reports on insulin's page are still read on insulin glargine's label. A record whose code names another drug than the one it is counted under (`label_other_drug_T`) is read as one with no code wherever it is read by its own code, never on that code's label; counting any product containing its ingredient, it is judged, as every record is, against the counted ingredient's own label. Counting the product alone, and on a combination's page, its flags are those of exactly that product's records, each by its own code: the ingredient alone, or exactly that combination, as the drug names step reads each record (`substance_T`). A release without `ingredient_rxnorm_T` reads every page the second way. The case window keeps each suspect drug's own flag, by its record's own code.

- `outcomes`: every flag, in the order the screens list and sort them, furthest from the label first: Not listed, Forms differ, Can't tell, Possibly listed, Listed, then those not compared with the label: a procedure, the disease it treats, not a medical event, no label found. The words are rule explorer-label-words.
- **Everything shows from the start.** Label status opens with every tick on, so every list opens on its true total. Clear all goes back to every tick on.
- `unexpected_only`: the ticks the one-click Unexpected only leaves on. Can't tell and no label found count as unexpected, because a reaction is unexpected until a label says otherwise; a procedure is inside it, because it can be the only sign of serious harm (a transplant or dialysis). The disease it treats and not a medical event are outside it. These are exactly the flags the data reads as unexpected (`expectedness` in rule label-flags), and the menu says what unexpected means in FDA's words: "not listed in the current labeling for the drug product" (21 CFR 314.80).
- A case counts under a flag when at least one of its reactions has that flag for the drug, so the counts add up to more than the cases.
- **Another form's label.** Where none of the forms the report could be has a label of its own, or the report does not say the form, the flag comes from the label of another form (`judged_on_T` names it), and its line and tip say which: "Listed on the injected label; no by-mouth label". Route families are named in plain words: by mouth, under the tongue, injected, inhaled, nasal, rectal, vaginal, patch, skin, eye, ear, other.
- `shown_as_uncertain`: a flag decided this way (a model's suggestion nobody has checked yet) shows and counts as Can't tell. A model's guess never shows as decided.
- **A drug's row.** A drug's reports can be of different forms, read against different labels. A drug's reaction resolves its reports' flags as the comparison resolves a record's forms. A report that found no label (one with no RxNorm code) decides the row only when no report found one. Then: the one flag they give when they agree; Forms differ, with each form's flag, when some read on the label and some not (their expectedness differs); otherwise the flag closest to the label, in the order of `closest_to_label` (the comparison's order, with Forms differ, which a record of unknown form can carry, after Listed), and its tip lists the others. Those all read unexpected, so Unexpected only shows the row either way and nothing is hidden.
- **When labels agree.** A drug's row, or a case's drug, can be read on more than one label that gives the same flag: a drug's reports may carry different RxNorm codes (valsartan's own and a combination holding it) or different forms. The label it names is then the first in the order of `label_tiebreak`, so the same release always names the same label: `own_label`, the drug's own label first, the one read for a record coded as the drug itself (`own_label` gives the RxNorm term type: a single ingredient's code for an ingredient, the combination's for a combination), because the label follows what is counted; `newest_label`, the label with the latest effective date; `setid`, the lower set ID. A flag read on no one label comes last. The labels named above a drug's Statistics table follow the same order within each form; how each is named is rule explorer-label-names.
- **On a drug's Statistics tab.** The Label column, after Reaction, gives each pair's flag: the drug's row for that reaction, matched by the reaction's name in lower case. Label status narrows the pairs to the ticked flags, its counts are the reactions in the list under the screen, and sorting by Label puts the flags in the order of `outcomes`, the highest EB05 first within each. The flags never change a number.
- `nothing_ticked`: what the address says when every tick is off (nothing counts), as `label=none`.

**Why:** FAERS reports are suspected events, not proven reactions; the flag only says whether today's label lists the event. Showing everything first keeps the totals true, and one click narrows to what a safety reviewer asks about first.
