## Running them

Every notebook reads a release folder built by the command line: `open-altio demo` builds one from FDA's latest quarter, `open-altio build` from every quarter. Point a notebook at it with `OPEN_ALTIO_RELEASE`, or with `RELEASE` in its first code cell. It is opened read only.

With the environment set up as `AGENTS.md` says (`uv sync --locked --extra dev`, which brings the notebooks' libraries):

```sh
OPEN_ALTIO_RELEASE=releases/2026Q2 uv run python scripts/run_nb.py 00_setup_and_inventory
uv run python scripts/run_nb.py --strip      # remove outputs, for a clean re-run
```

`scripts/run_nb.py` runs the notebooks named, or every one, with the package from this working tree. Notebook 02 also reads `OPEN_ALTIO_BEFORE` (the release with its rules off) and `OPEN_ALTIO_ZIPS` (FDA's zips); notebook 03 reads `OPEN_ALTIO_ZIPS` when it is set; notebooks 05 and 08 read the reference files above, notebook 10 the licensed MedDRA part of a release on which `python -m open_altio.faers labels` has run, notebook 11 the label step's tables (`OPEN_ALTIO_LABELS`), and notebook 09 DiAna's ATC file (`OPEN_ALTIO_DIANA_ATC`), the reviewed indication list (`OPEN_ALTIO_INDICATION_LIST`), the review's staged rows (`OPEN_ALTIO_STAGED_ROWS`) and WHO's index (`OPEN_ALTIO_WHO_DIR`). Executed copies with outputs, each notebook's cards as JSON and the working tables of notebooks 02, 03, 04 and 05 go to `notebooks/out/` (or `OPEN_ALTIO_INSIGHTS_OUT`), which git ignores.

`tests/faers/test_notebooks.py` checks the committed notebooks on every run, and runs 00, 01, 07 and 90, 02 given its two releases, 03 given a release built from every quarter, and 08 given its reference folders, with `uv run pytest -m slow tests/faers/test_notebooks.py`.

## Rules for a notebook

- Commit with the outputs of a run on the release named in the first cell: copy the executed copy from `notebooks/out/notebooks/` over the notebook. Outputs that show MedDRA content beyond the Preferred Term names (the hierarchy, SMQs or codes) are licensed by the MSSO and are not published: clear that cell's output and put in its place one stderr stream output, in ANSI red, reading "Output not shown: it contains MedDRA content beyond the Preferred Term names (the hierarchy, SMQs or codes). MedDRA is licensed by the MSSO, so we cannot publish it. To see this output, run the notebook with your own MedDRA files; you need a MedDRA subscription from the MSSO." `tests/faers/test_notebooks.py` refuses a committed output that carries a MedDRA hierarchy column.
- The first cell says what the notebook reads and how to build it; the first code cell names the release in `RELEASE = None`.
- A chart for every analysis cell, titled with its claim: the point the data supports, computed from it where it holds a number. The subtitle says how to read the chart and the question it answers. `open_altio.faers.insights.cards.notebook` holds the shared look: `setup()`, `title()`, the event guides on time axes, bar labels and the heatmap.
- A finding worth keeping becomes a card (`src/open_altio/faers/insights/cards/`) and, when it explains a step, a page under `docs/methods/`.
- A finding that changes the pipeline links to the funnel step that acts on it.
