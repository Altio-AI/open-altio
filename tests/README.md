# Tests

The suite mirrors `src/open_altio/`:

- `faers/`: building a release from FDA's quarterly files, one module for each module it tests: `test_load.py` (FDA's files read verbatim), `test_derive.py` and `test_eras.py` (the derived steps), `test_duplicates.py`, `test_release.py` (the release folder), `test_user_rules.py` (a build under a person's own rules), `test_explorer_db.py`, `test_meddra_licensed.py`, `test_build.py`, `test_fda.py`, `test_formats.py`; `drugnames/` (the drug-name step), `insights/` (`methods.json` and the insight cards), `test_notebooks.py` (the committed notebooks, and running them over a real release) and `test_parity.py` (a full build against counts made apart from this code).
- `explorer/`: the explorer run on its own, as one person runs it on their own machine (LocalAccess, no sign-in), one module for each module it tests: `test_filters.py` (each filter, and the product, reactions and drugs a page adds), `test_explore.py` (counts, charts, the case list, one case, and a product's six settings), `test_caselist.py` (the cases behind every count of a drug's events, a group, the Overview and an event's breakdowns, listed by their `cases_query`), `test_casecolumns.py` (a page of the case list: `total`, `case_number`, every order both ways with Not given last, and what `detail=columns` gives about the drug, checked against the case read whole), `test_counted.py` (a counted question: each value's `cases_query` lists exactly its cases, a `by` outside the rule and a filter value that is not a choice, and the same bytes twice), `test_recount.py` (the second count agrees with every counted question, by every field and under filters in combination, with MedDRA and under Label status; a planted difference is answered with both counts, never agreeing; every parameter `filters.py` reads is one the second count reads; the count written as one query holds each value as a constant that is exactly that value), `test_eventlist.py` (a drug's events, and a group of reactions counted as one), `test_counting.py` (every count of distinct cases, never rows), `test_search.py`, `test_meddra.py`, `test_meddra_names_release.py` (slow: every rule naming MedDRA's terms against the MedDRA of the release named by `OPEN_ALTIO_REAL_RELEASE`), `test_live_release.py` (release.py: where the live release is), `test_sql.py` (read-only SQL within its limits, and the query behind every counted question run there to exactly its counts, by every field and under filters in combination, values holding quotes or SQL text included; MedDRA's tables only for a viewer who may see them), `test_export.py`, `test_downloads.py`, `test_api.py`, `test_access.py` (the access hook a host plugs in), `test_pages.py`, `test_event_breakdowns_page.py` (the opened event's breakdowns in a browser: the groups and lines against `/api/breakdowns`, a line pressed, its list's counts against the answer and each box's filter, a tick narrowing the other panes, Deselect all, Show all and + Add a filter's new fields), `test_event_compared_page.py` (the opened event's Compared tab in a browser: each row's numbers against the published answers, a host's `classes: false`, a drug's read-only view with no host's cell, and Back), `test_event_page.py` (an event opened under its row by a host, in a browser: its copy, line and bar, the tabs, Dates and its window, + Add a filter narrowing, the layers that stick, a host's places and a registered pane), `test_event_cases_page.py` (its Cases tab and a case read in place: the columns ticked, a head's menu that sorts and narrows with counts, a duplicate under its case, a case opened in place and back to the same page, nothing moving as rows load), `test_app.py` and `test_page.py` (the page in a browser: addresses, clicks, keys, the side panel and a host's page modules, in Playwright's headless Chromium, skipped where it is not installed), `test_rules_api.py` and `test_rebuild.py` (the rules page's choices and the rebuild with them), `test_outbox.py` and `test_outbox_browser.py` (Improve this on someone's own machine: the outbox, and the page sending to a fake of Altio's service in the browser). `explorer/conftest.py` lists its fixtures.
- `rulebook/`: reading rule files, the catalogue of data rules, and a person's own rules (`rules.toml`).
- `cli/`: the command line, one module for each command module: `test_data.py` (demo, fetch and build, against FDA's server faked on 127.0.0.1 by `open_altio.testing.fdaserver`), `test_serve.py`, `test_doctor.py`, `test_report.py` (the bug form's own fields), and `test_cli.py` (tasks, help, refusals and crashes).
- `labelreview/`: the label review: the coding question, batches, gates, the agent hand-over and its retries with a fake agent, terms checked against the fake MedDRA, decisions, the blind redo, freezing, the rule check and the review page.
- `contract/`: Open Altio's written contract (`docs/reference/contract.md`), the names a product built on Open Altio may build on, checked against the invented release: `test_version.py` (one contract version, named on every page of it), `test_release.py` (a release names its source and format, and every reader refuses any other folder), `test_questions.py` (every `/api` route published or the explorer's own; each published answer's keys against `snapshots/api.json`; a route and its function answering the same, naming the release; the same answer twice, and from an earlier folder after another is live), `test_access.py` (the kinds the server announces and the page reports, each listed, and nothing announced for viewing a question), `test_page.py` (in a browser: `extend()` and `slot()` refuse what is not listed, every place drawn is listed, `brand` and `kept`, no word of a product's workflow on the page), `test_rules_folders.py` (a product's rules folder and its prefix) and `test_routes.py` (a host's routes first, the explorer's paths refused). A change that fails it either keeps the old names, or raises `CONTRACT_VERSION` and writes the snapshot again with `scripts/contract_snapshot.py`.
- At the top: `test_meddra_names_in_repo.py` (slow: no MedDRA group or class name, and no code, in any file, against the list in the licensed part of the release named by `OPEN_ALTIO_REAL_RELEASE`; without it, it skips, saying it could not check), the rules folder, where files live (`test_paths.py`), memory facts (`test_machine.py`), Windows by simulation (`test_windows.py`: every module imports without the Unix-only modules; that no path is typed with a separator is a code gate in `scripts/check.py`), and that the open package stands alone (`test_open_package_alone.py`: no module imports the hosted service, and the package installs as a wheel and runs without it).

Run from the repository root:

```sh
uv run pytest -q              # fast suite, a few minutes
uv run pytest -q -m slow      # over the real FAERS quarters, and a fresh install
```

The browser tests need Playwright's headless shell (`uv run playwright install --only-shell chromium`). Without it they skip, unless `OPEN_ALTIO_REQUIRE_BROWSER` is set, as CI sets it: then they fail, so a green suite has drawn every page.

- How the pages look is checked by screenshots, not by tests that read the CSS: `scripts/screens.py` shoots every screen before and after a change and compares them pixel by pixel.
- One seam: a fake FDA release built once per session (`open_altio.testing.fakefda`), with its fixtures in `open_altio.testing.fixtures` (`release`, `rel`, `licensed_release`, ...), which `conftest.py` imports. What a test expects is read from the release's own files through `rel`, so the code is checked against the release and not against itself.
- Every limit a test uses is read from `rules/` with `rulebook.value(...)`, never typed in; `test_rules.py` fails if a test of a rule types one of its values. A test that needs another limit runs under `open_altio.testing.rules.rules_with`; a build with other data rules takes `user_rules=UserRules(...)`, as a person's `rules.toml` gives it.
- A test names what it proves in its name and docstring, and tests both what the code does and what it refuses.

Browser walks (`walks/`) click through a page in headless Chrome at three widths; `walks/README.md`
says how to run them.

## The hosted service

`service/` is the hosted service, with a suite of its own in `service/tests/`: sign-in, the people Altio approves, staff and Administration, the usage log, the download store, emails and the service's page modules. It builds the explorer with its own access hook, so what the explorer does with the data is tested here, not there. Install both packages into one environment and run it from `service/`:

```sh
uv pip install -e service
cd service && uv run --project .. pytest -q
```
